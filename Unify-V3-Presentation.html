01 · The problem

Linked work drifts apart silently, and nobody finds out until it's expensive

A feature lives in six tools at once: a Figma frame, a GitHub PR, a Jira ticket, a Notion spec, a Slack thread, a Vercel deploy. Each tool holds its own copy of the truth, under its own identity, behind its own API. No shared identifier connects them, and no tool watches the connections.

During work

References die at creation

"See the Figma link in the ticket" is a snapshot, not a live relationship. When the design changes on Tuesday, the PR built on Monday's version has no idea.

The reconciler

A human is the sync engine

Someone — usually the PM — manually cross-checks tickets against PRs against designs. It's unowned, unreliable work that scales with team size.

The cost

Drift surfaces late, as bugs

The mismatch is discovered at QA, deployment, or standup — the most expensive possible moment — and triggers rework and cross-tool archaeology to find out what happened.

02 · How Unify solves it

A relationship graph over existing tools, with drift rules on top

Unify connects tools instead of replacing them. Four layers, each solving one sub-problem — the bottom two are plumbing, the top two are the contribution.

Ingestevents out of silos

Webhook receivers with polling fallback per tool, normalizing every event into one schema: actor, entity, action, timestamp, references.

Linkone identity per work item

Entity resolution builds the cross-tool graph automatically from textual references — a PR mentioning JIRA-482, branch names, Figma URLs in tickets — with manual linking for the gaps. Grounded in 20+ years of traceability-link-recovery research.

Detectthe headline value

Rules over the graph compare state and timestamps of linked entities: design changed after implementation began, PR merged while its ticket is still In Progress, two open PRs touching the same component.

Routeprecision over volume

Each conflict reaches only the person whose work it affects — the designer, the developer, or the PM — on their channel, at their frequency, above their noise threshold. Success is measured as a low dismissal rate.

05 · Slide A Core features — must be delivered

Five features define the project; two of them are the contribution

Foundation

Tool integrations

Figma, GitHub, Jira, Vercel, Notion, Slack. Nothing works without events leaving the silos.

Foundation

Event ingestion & normalization

Webhooks with polling fallback, mapped to one internal schema. Reliability here bounds everything above it.

Backbone

Cross-tool relationship layer

Entity resolution across tools — automatic from textual references, manual for the gaps. Applies established traceability techniques; every other feature reads from this graph.

★ Contribution

Conflict detection engine

Workflow-state drift rules over linked entities. This is the feature no existing product ships, and the headline value of the project.

★ Contribution

Role-aware notification engine

Detection is worthless if it spams the wrong person. Precision routing with a measurable target: low dismissal rate.

06 · Slide B Secondary features — supporting & nice-to-have

Valuable, cuttable, and none of them the point

Supporting UI

Unified dashboard

Role-tailored live widgets from every connected tool. A read-model over the graph — presentation, not new intelligence, and table stakes in this market.

Supporting UI

Shared activity feed

One chronological timeline of normalized events. Falls out of the ingestion layer almost for free; useful, but not a differentiator.

Future · advisory only

AI layer

Change summaries across linked entities, suggested missing links, standup generation, natural-language status queries ("what's blocking the checkout redesign?"). Recommends — humans decide. Deliberately future work: Unblocked and Rovo already own this ground.

Future

Analytics & long-tail integrations

Advanced analytics dashboards and niche tools beyond the six launch integrations. Deferred until the core proves precision.
